# Events

The events that can be generated by the ZigBee PRO stack are enumerated in the structure `ZPS_teAfEventType`\(from the AF API\), shown below.

```
typedef enum {
ZPS_EVENT_NONE,                                                /* 0, 0x00 */
ZPS_EVENT_APS_DATA_INDICATION,                                 /* 1, 0x01 */
ZPS_EVENT_APS_DATA_CONFIRM,                                    /* 2, 0x02 */
ZPS_EVENT_APS_DATA_ACK,                                        /* 3, 0x03 */
ZPS_EVENT_NWK_STARTED,                                         /* 4, 0x04 */
ZPS_EVENT_NWK_JOINED_AS_ROUTER,                                /* 5, 0x05 */
ZPS_EVENT_NWK_JOINED_AS_ENDDEVICE,                             /* 6, 0x06 */
ZPS_EVENT_NWK_FAILED_TO_START,                                 /* 7, 0x07 */
ZPS_EVENT_NWK_FAILED_TO_JOIN,                                  /* 8, 0x08 */
ZPS_EVENT_NWK_NEW_NODE_HAS_JOINED,                              /* 9, 0x09 */
ZPS_EVENT_NWK_DISCOVERY_COMPLETE,                               /* 10, 0x0a */
ZPS_EVENT_NWK_LEAVE_INDICATION,                                 /* 11, 0x0b */
ZPS_EVENT_NWK_LEAVE_CONFIRM,                                    /* 12, 0x0c */
ZPS_EVENT_NWK_STATUS_INDICATION,                                /* 13, 0x0d */
ZPS_EVENT_NWK_ROUTE_DISCOVERY_CONFIRM,                           /* 14, 0x0e */
ZPS_EVENT_NWK_POLL_CONFIRM,                                      /* 15, 0x0f */
ZPS_EVENT_NWK_ED_SCAN,                                           /* 16, 0x10 */
ZPS_EVENT_ZDO_BIND,                                              /* 17, 0x11 */
ZPS_EVENT_ZDO_UNBIND,                                            /* 18, 0x12 */
ZPS_EVENT_ZDO_LINK_KEY,                                          /* 19, 0x13 */
ZPS_EVENT_BIND_REQUEST_SERVER,                                   /* 20, 0x14.*/
ZPS_EVENT_ERROR,                                                 /* 21, 0x15 */
ZPS_EVENT_APS_INTERPAN_DATA_INDICATION,                           /* 22, 0x16 */
ZPS_EVENT_APS_INTERPAN_DATA_CONFIRM,                              /* 23, 0x17 */
ZPS_EVENT_APS_ZGP_DATA_INDICATION,                                /* 24, 0x18 */
ZPS_EVENT_APS_ZGP_DATA_CONFIRM,                                   /* 25, 0x19 */
ZPS_EVENT_TC_STATUS,                                              /* 26, 0X1A */
ZPS_EVENT_NWK_DUTYCYCLE_INDICATION,                               /* 27, 0x1B */
ZPS_EVENT_NWK_FAILED_TO_SELECT_AUX_CHANNEL,                       /* 28, 0x1C */
ZPS_EVENT_NWK_ROUTE_RECORD_INDICATION,                            /* 29, 0x1D */
ZPS_EVENT_NWK_FC_OVERFLOW_INDICATION,                             /* 30, 0x1E */
ZPS_ZCP_EVENT_FAILURE
} ZPS_teAfEventType;
```

The events in the above structure are outlined in the table below.

**Note:** The AF structures which contain the data for the above events are detailed in [Section 8.2.2, Event Structures](event_structures.md) .

**ZigBee PRO stack Events**

|**Stack Event**|**Description**|
|--|--|
|ZPS\_EVENT\_NONE|Used as initial value in structure which receives a message collected from a message queue.|
|ZPS\_EVENT\_APS\_DATA\_INDICATION|Indicates that data has arrived on the local node. The event provides information about the data packet through the structure `ZPS_tsAfDataIndEvent`- see [Section 8.2.2.3](zps_tsafdataindevent.md).|
|ZPS\_EVENT\_APS\_DATA\_CONFIRM|Indicates whether a sent data packet has been successfully passed down the stack and has reached the next hop node toward its destination. The results are reported through the structure `ZPS_tsAfDataConfEvent`- see [Section 8.2.2.4](zps_tsafdataconfevent.md).|
|ZPS\_EVENT\_APS\_DATA\_ACK|Indicates that a sent message has reached its destination node. Details of the received acknowledgment are reported through the structure `ZPS_tsAfDataAckEvent`- see [Section 8.2.2.5](zps_tsafdataackevent.md).|
|ZPS\_EVENT\_NWK\_STARTED|Indicates that network has started on Coordinator. This is reported through the structure `ZPS_tsAfNwkFormationEvent`- see [Section 8.2.2.6](zps_tsafnwkformationevent.md). ‘Permit joining’ state is set as specified in APL data structure.|
|ZPS\_EVENT\_NWK\_JOINED\_AS\_ROUTER|Indicates that device has successfully joined network - as Router and reports allocated network address through the structure `ZPS_tsAfNwkJoinedEvent`- see [Section 8.2.2.7](zps_tsafnwkjoinedevent.md).|
|ZPS\_EVENT\_NWK\_JOINED\_AS\_ENDDEVICE|Indicates that device has successfully joined network as End Device and reports allocated network address through the structure `ZPS_tsAfNwkJoinedEvent`- see [Section 8.2.2.7](zps_tsafnwkjoinedevent.md).|
|ZPS\_EVENT\_NWK\_FAILED\_TO\_START|Indicates that network has failed to start on Coordinator.|
|ZPS\_EVENT\_NWK\_FAILED\_TO\_JOIN|Indicates that device failed to join network. This is reported through the structure `ZPS_tsAfNwkJoinFailedEvent`- see [Section 8.2.2.8](zps_tsafnwkjoinfailedevent.md)|
|ZPS\_EVENT\_NWK\_NEW\_NODE\_HAS\_JOINED|Indicates to Coordinator or Router that new node has joined as child and reports details of new child through the structure `ZPS_tsAfNwkJoinIndEvent`- see [Section 8.2.2.10](zps_tsafnwkjoinindevent.md).|
|ZPS\_EVENT\_NWK\_DISCOVERY\_COMPLETE|Indicates that network discovery on Router or End Device has finished and reports details of detected net- work through the structure `ZPS_tsAfNwkDiscoveryEvent`- see [Section 8.2.2.9](zps_tsafnwkdiscoveryevent.md). This event \(and associated structure\) is generated for each network detected.|
|ZPS\_EVENT\_NWK\_LEAVE\_INDICATION|Indicates that a neighboring node has left the network or a remote node has requested the local node to leave. Details are provided through the structure `ZPS_tsAfNwkLeaveIndEvent`- see [Section 8.2.2.11](zps_tsafnwkleaveindevent.md).|
|ZPS\_EVENT\_NWK\_LEAVE\_CONFIRM|Reports the results of a node leave request issued by the local node. The results are reported through the structure `ZPS_tsAfNwkLeaveConfEvent`- see [Section 8.2.2.12](zps_tsafnwkleaveconfevent.md).|
|ZPS\_EVENT\_NWK\_STATUS\_INDICATION|Reports network status event from a remote or local node through the structure `ZPS_tsAfNwkStatusIndEvent`- see [Section 8.2.2.13](zps_tsafnwkstatusindevent.md).|
|ZPS\_EVENT\_NWK\_ROUTE\_DISCOVERY\_CONFIRM|Indicates that a route discovery has been performed. The results are reported in the structure `ZPS_tsAfNwkRouteDiscoveryConfEvent`- see [Section](zps_tsafnwkroutediscoveryconfevent.md)[8.2.2.14](zps_tsafnwkroutediscoveryconfevent.md).|
|ZPS\_EVENT\_NWK\_POLL\_CONFIRM|Generated on an End Device to indicate that a poll request submitted to its parent has completed. The outcome of the poll request is indicated through the structure `ZPS_tsAfPollConfEvent`- see [Section](zps_tsafpollconfevent.md)[8.2.2.15](zps_tsafpollconfevent.md).|
|ZPS\_EVENT\_NWK\_ED\_SCAN|Indicates that an ‘energy detect’ scan in the 2.4-GHz radio band has completed. The results of the scan are reported through the structure `ZPS_tsAfNwkEdScanConfEvent`- see [Section 8.2.2.16](zps_tsafnwkedscanconfevent.md).|
|ZPS\_EVENT\_ZDO\_BIND|Indicates that the local node has been successfully bound to one or more remote nodes. The details of the binding are reported through the structure `ZPS_tsAfZdoBindEvent`- see [Section 8.2.2.18](zps_tsafzdobindevent.md).|
|ZPS\_EVENT\_ZDO\_UNBIND|Indicates that the local node has been successfully unbound from one or more remote nodes. The details of the unbinding are reported through the structure `ZPS_tsAfZdoUnbindEvent`- see [Section 8.2.2.19](zps_tsafzdounbindevent.md).|
|ZPS\_EVENT\_ZDO\_LINK\_KEY|Indicates that a new application link key has been received and installed, and is ready for use. The details of the link key are reported through the structure `ZPS_tsAfZdoLinkKeyEvent`- see [Section 8.2.2.20](zps_tsafzdolinkkeyevent.md).|
|ZPS\_EVENT\_BIND\_REQUEST\_SERVER|Indicates the results of a bound data transmission. The results are reported through the structure `ZPS_tsAfBindRequestServerEvent`- see [Section 8.2.2.21](zps_tsafbindrequestserverevent.md).|
|ZPS\_EVENT\_ERROR|Indicates that an error has occurred on the local node. The nature of the error is reported through the structure `ZPS_tsAfErrorEvent`- see [Section 8.2.2.17](zps_tsaferrorevent.md).|
|ZPS\_EVENT\_APS\_INTERPAN\_DATA\_INDICATION|Indicates that an inter-PAN communication has arrived \(from a node in another network\). Details of the inter-PAN communication are reported through the structure `ZPS_tsAfInterPanDataIndEvent`- see [Section](zps_tsafinterpandataindevent.md) [8.2.2.22](zps_tsafinterpandataindevent.md).|
|ZPS\_EVENT\_APS\_INTERPAN\_DATA\_CONFIRM|Indicates that an inter-PAN communication \(to another network\) has been sent by the local node and an acknowledgment has been received from the first hop node \(this acknowledgment is not generated in the case of a broadcast\). The status of the inter-PAN communication is reported through the structure `ZPS_tsAfInterPanDataConfEvent`- see [Section](zps_tsafinterpandataconfevent.md) [8.2.2.23](zps_tsafinterpandataconfevent.md).|
|ZPS\_EVENT\_TC\_STATUS|Indicates whether the negotiation for a link key with the Trust Centre has been successful and, if so, provides the key. These details are provided through the structure `ZPS_tsAfTCstatusEvent`- see [Section](zps_tsaftcstatusevent.md) [8.2.2.24](zps_tsaftcstatusevent.md).|
|ZPS\_EVENT\_NWK\_DUTYCYCLE\_INDICATION|Relevant only for Sub Gig. Indicates the duty cycle state.|
|ZPS\_EVENT\_NWK\_FAILED\_TO\_SELECT\_AUX\_CHANNEL|Relevant for Sub Gig only. Failure on a multiMAC interface to form a network on the selected channel.|
|ZPS\_EVENT\_NWK\_ROUTE\_RECORD\_INDICATION|Indicates when a route record is received.|
|ZPS\_EVENT\_NWK\_FC\_OVERFLOW\_INDICATION|Indicates the overflow of the frame counter when frame counter &gt; 0x80000000.|

**Note:** Event handling is outlined in "[Appendix A](handling_stack_events.md)".
